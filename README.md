# MoviesHub

MoviesHub is a movie data pipeline and dashboard. It retrieves movie data from TMDB, cleans it, creates features, stores the resulting records in MongoDB, and trains models used by a Streamlit dashboard.

## Project layout

- `src/extract.py` fetches popular movies and their details from TMDB into `data/raw/movies.json`.
- `src/clean.py` removes duplicate movies and writes `data/clean/movies_clean.csv`.
- `src/build_features.py` creates derived fields and writes `data/features/movies_features.csv`.
- `src/load_mongodb.py` upserts the feature records into `moviesHub_db.movies`, keyed by `movie_id`.
- `src/train_models.py` trains classification, clustering, and recommendation artifacts in `models/`.
- `src/mongodb.py` is a separate manual loader and query example. It reads the clean CSV, clears the MongoDB collection, inserts its rows, and prints sample queries. **Do not run it if you want to preserve the current collection.**
- `dags/movies_pipeline.py` defines the Airflow workflow that runs extraction, cleaning, feature generation, MongoDB upsert, then model training.
- `dashboard/app.py` is the Streamlit application.
- `notebooks/` contains the exploratory analysis and notebook versions of the data science work.

## Requirements

- Docker and Docker Compose
- A TMDB API read access token

## Configure environment

Create a local `.env` file from the example:

```bash
cp .env.example .env
```

Set `TMDB_ACCESS_TOKEN` to your TMDB access token. Set the MongoDB and Mongo Express passwords to values you choose. Keep `.env` private; it contains credentials.

The extraction script uses `URL` as the TMDB movie-list endpoint. The example uses the popular movies endpoint.

## Run with Docker Compose

Build and start MongoDB, Mongo Express, Airflow, and Streamlit:

```bash
docker compose up --build -d
```

Open the services:

- Airflow: <http://localhost:8080>
- Streamlit dashboard: <http://localhost:8501>
- Mongo Express: <http://localhost:8081>

In Airflow, enable and trigger the `movieshub_pipeline` DAG. Its tasks run in this order:

```text
extract -> clean -> features -> mongodb_upsert -> train_and_save_ml_artifacts
```

The Airflow task writes the resulting datasets and model artifacts into the project directories mounted in Docker. The dashboard reads movie records from MongoDB when available and falls back to the feature CSV. Classification, clustering, and recommendation pages require the model artifacts produced by the final pipeline task.

To stop the services while keeping stored Docker volumes:

```bash
docker compose down
```

To remove containers and their stored MongoDB/Airflow volumes:

```bash
docker compose down -v
```

## Run scripts locally

Install Python packages and prepare `.env` as above:

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Start MongoDB separately, then run the pipeline scripts in sequence:

```bash
python src/extract.py
python src/clean.py
python src/build_features.py
python src/load_mongodb.py
python src/train_models.py
```

For a local MongoDB connection, `src/load_mongodb.py` uses `MONGO_HOST` (defaults to `localhost`) and `MONGO_PORT` (defaults to `27017`), plus `MONGO_INITDB_ROOT_USERNAME` and `MONGO_INITDB_ROOT_PASSWORD` from `.env`. `src/mongodb.py` instead uses `MONGO_URI`.

## Data and generated files

The pipeline creates or updates these files:

```text
data/raw/movies.json
data/clean/movies_clean.csv
data/features/movies_features.csv
models/classification_pipeline.joblib
models/clustering_pipeline.joblib
models/recommendation_pipeline.joblib
```

The model artifacts are generated by `src/train_models.py`; run the pipeline before opening model-powered dashboard sections if those files are not present.
